# AI Forecast Terminal — дизайн

Дата: 2026-11-17
Статус: черновик, ждёт одобрения

## Зачем

Дипломный проект: «Система финансового прогнозирования на основе искусственного интеллекта».
Нужен **веб-сайт**, который показывает историю котировок акций и прогноз, построенный
моделями машинного обучения, со сравнением точности моделей.

Для комиссии важны две вещи:
1. Настоящая ИИ-часть: несколько моделей, честная проверка на исторических данных, метрики.
2. Внешний вид: сайт должен выглядеть как профессиональный инструмент трейдера,
   а не как типовой сгенерированный ИИ интерфейс.

## Цели

- Данные по акциям из индекса **Nasdaq-100** (≈100 компаний), дневные свечи (OHLCV).
- Для выбранной акции: свечной график истории + линия прогноза на N дней вперёд
  с доверительным интервалом.
- Несколько моделей прогноза, переключаемых в интерфейсе, и таблица их точности
  на отложенной выборке (бэктест).
- Ощущение терминала трейдера: плотная информация, тёмная тема, моноширинные цифры,
  зелёный/красный для роста/падения, тикер-лента, список-вотчлист.
- Демо работает **без интернета** (данные лежат в проекте).

## Не цели

- Реальное время / внутридневные котировки. Данные дневные.
- Торговля, ордера, кошельки, авторизация пользователей.
- Криптовалюты и другие рынки (архитектура позволяет добавить позже, но не сейчас).
- Мобильная версия как основная. Сайт рассчитан на десктоп; на узком экране
  должен не ломаться, но не обязан быть удобным.

## Анти-цели (провал, даже если всё работает)

- «ИИ-шный» вид: одинаковые карточки со скруглением 12–16px, тени, фиолетово-синие
  градиенты, эмодзи, большие пустые отступы, шрифт Inter по умолчанию, glassmorphism.
- Фейковые данные, выдаваемые за настоящие (например, имитация «живых» тиков,
  которых нет в источнике).
- Прогноз без указания точности: каждый прогноз показывается рядом с метриками модели.
- Формулировки в духе инвестиционного совета. В интерфейсе дисклеймер:
  учебный проект, не инвестиционная рекомендация.

## Ограничения

- Машина разработки: Windows 11, Node 26, Python 3.14. Rust не установлен и не нужен.
- Обучение моделей на CPU (без GPU).
- Только бесплатные источники данных.

## Подходы (рассмотрено)

| Подход | Суть | Плюсы | Минусы |
|---|---|---|---|
| **A. Python-бэкенд + собственный фронтенд** ✅ выбран | FastAPI + модели на Python; фронтенд вручную, графики на Lightweight Charts | Сильнейшая ИИ-часть, стандарт для дипломов, «биржевые» графики из коробки | Два языка в проекте |
| B. Rust-бэкенд (axum) + тот же фронтенд | Модели на linfa/burn | Эффектно на защите, быстро | Нужно ставить Rust, ML-экосистема слабее, LSTM сложнее |
| C. Всё в браузере (TensorFlow.js) | Статичный сайт | Проще развернуть | Слабая архитектура «системы», тяжёлые модели тормозят |

Выбран **A** (решение пользователя).

## Решения пользователя

- Формат: веб-сайт.
- Рынок: акции Nasdaq-100.
- Подход A: Python-бэкенд + собственный фронтенд.
- Дизайн: ощущение терминала трейдера (Binance, трейдеры из фильмов), но не клон и не шаблон.
- В проекте не упоминаются конкретные люди (студент, руководитель).

## Решения исполнителя (предложены, можно поправить)

### Данные
- Источник: Yahoo Finance через библиотеку `yfinance`.
- Отдельный скрипт `scripts/fetch_data.py` один раз скачивает дневные OHLCV за ~10 лет
  для всех тикеров и сохраняет в `data/` (Parquet или CSV). Сайт читает только локальные файлы.
- Список компаний Nasdaq-100 хранится статичным файлом (`data/nasdaq100.json`:
  тикер, название, сектор) с датой актуальности состава.
- Обновление данных — повторный запуск скрипта, а не автоматически.

### Модели
Четыре модели, от простой к сложной, чтобы было что сравнивать:
1. **Naive** (завтра = сегодня) — базовая линия, с которой сравниваются остальные.
   Если модель не обгоняет Naive на какой-то акции, это показывается честно
   (в таблице выделяется) — это нормальный научный результат, а не провал.
   Чтобы у моделей был шанс, целевая переменная — доходность, а не сырая цена.
2. **ARIMA** (statsmodels) — классический статистический метод.
3. **Градиентный бустинг** (LightGBM или sklearn HistGradientBoosting) на признаках:
   лаги доходностей, скользящие средние, волатильность, RSI, объём.
4. **LSTM** (PyTorch) — нейросеть по окну последних 60 дней.

- Прогнозируется доходность/цена закрытия на горизонт 1–30 дней.
- Доверительный интервал: из модели, где возможно (ARIMA), иначе по распределению
  ошибок на бэктесте.
- Бэктест: последние ~12 месяцев отложены; метрики MAE, RMSE, MAPE и
  **точность направления** (угадан ли рост/падение).
- Обучение заранее: скрипт `scripts/train_all.py` обучает модели по всем тикерам
  и сохраняет прогнозы и метрики. API отдаёт готовое.
- Переобучение одной акции из интерфейса — **желательно, но не обязательно**
  (решение исполнителя): фоновая задача с индикатором прогресса; новые результаты
  заменяют старые только после успешного завершения. Делается в последнюю очередь.

### Бэкенд
- FastAPI. Эндпоинты (примерно):
  - `GET /api/tickers` — список с последней ценой, изменением за день, спарклайном.
  - `GET /api/candles/{ticker}` — история OHLCV.
  - `GET /api/forecast/{ticker}?model=&horizon=` — прогноз + интервал.
  - `GET /api/metrics/{ticker}` — метрики всех моделей.
  - `GET /api/overview` — данные для тепловой карты рынка.
- Бэкенд же раздаёт собранный фронтенд — один процесс для запуска на защите.

### Фронтенд
- Vite + TypeScript, **без UI-китов** (никаких Tailwind-компонентов, MUI, shadcn):
  вся вёрстка вручную на CSS Grid.
- Графики: TradingView **Lightweight Charts** (Apache-2.0) — свечи, объём, линия прогноза,
  полоса интервала.
- Один экран-терминал, разбитый на панели тонкими линиями (1px), без карточек:

```
┌──────────────────────────────────────────────────────────────────────┐
│ ▲ AAPL 231.40 +1.2%   ▼ MSFT 418.02 −0.4%   ▲ NVDA … (тикер-лента)    │
├─────────────┬────────────────────────────────────────┬───────────────┤
│ ВОТЧЛИСТ    │ NVDA  NVIDIA Corp      142.31  +2.04%   │ МОДЕЛЬ        │
│ поиск…      │ ┌────────────────────────────────────┐ │ ○ Naive       │
│ AAPL  231.4 │ │  свечи ............ ╌╌╌прогноз╌╌╌  │ │ ○ ARIMA       │
│ ADBE  512.0 │ │                  ░░░интервал░░░   │ │ ● LSTM        │
│ AMD   148.9 │ └────────────────────────────────────┘ │ горизонт 7д   │
│ …           │  объём ▁▂▃▅▂▁                          │ прогноз +3.1% │
│             │ 1М 3М 6М 1Г 5Л                          │ MAPE 2.4%     │
├─────────────┴────────────────────────────────────────┴───────────────┤
│ СРАВНЕНИЕ МОДЕЛЕЙ   MAE   RMSE   MAPE   НАПРАВЛЕНИЕ    │ ТЕПЛОКАРТА  │
└──────────────────────────────────────────────────────────────────────┘
```

- Визуальный язык:
  - Почти чёрный фон с лёгким тёплым/холодным оттенком, не чистый #000.
  - Скругления 0–2px. Разделители — линии, а не тени.
  - Цифры — моноширинный шрифт с табличными цифрами (например, JetBrains Mono /
    IBM Plex Mono); подписи — узкий гротеск (например, IBM Plex Sans Condensed).
    Точный выбор — за исполнителем, но не Inter/Roboto по умолчанию.
  - Мелкие UPPERCASE-подписи разделов с разрядкой.
  - Цвета роста/падения — не кислотные; акцентный цвет один.
  - Микроанимации: подсветка ячейки при смене значения, прорисовка линии прогноза.
  - Клавиатурная навигация по вотчлисту (↑/↓, `/` — поиск) — как в терминалах.

## Оставлено исполнителю

- Точная палитра, шрифты, размеры, анимации — в рамках визуального языка выше.
- Гиперпараметры моделей, набор признаков, длина окна.
- Формат хранения данных и кэша.
- Структура папок и тесты.

## Язык

- Интерфейс на **русском** (решение пользователя), без переключателя языков.
  Тикеры и названия компаний — в оригинале (латиница). Шрифты должны поддерживать кириллицу.

## Срок и приоритеты

Защита — **меньше чем через месяц** (решение пользователя). Порядок работ (решение исполнителя):

1. **Ядро** — должно работать первым:
   скачивание данных, все четыре модели (включая LSTM — это главная «ИИ»-часть),
   бэктест и метрики, API, экран-терминал: вотчлист, свечной график с прогнозом
   и интервалом, панель модели, таблица сравнения моделей. Дисклеймер.
2. **Полировка**: тикер-лента, микроанимации, клавиатурная навигация, спарклайны в вотчлисте.
3. **Если успеем**: тепловая карта рынка, переобучение из интерфейса.

Строгая проверка по нескольким горизонтам (walk-forward) — вне объёма.
